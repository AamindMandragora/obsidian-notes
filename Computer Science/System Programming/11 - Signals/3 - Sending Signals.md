Signals can be generated by users (through `CTRL-C` or `kill`), the system (`SIGSEGV` on bad access), and other processes (low-stakes IPC). However, in the last case, there are many drawbacks to using signals for communication, so we'll usually use other methods..

We can temporarily pause a running process by sending it a `SIGSTOP`, and if the signal succeeds, the process won't be allocated any more CPU time. We can send `SIGCONT` to make the process resume.

Processes send signals using `kill(pid_t pid, int sig)`, and we can send signals from the terminal using `kill -SIG pid`. We can pass in the signal's number or the name. We can use `ps` to find the `pid` of a process, or we can use `killall`, which will try to match the name of the process to a currently running one. If the process doesn't have root privileges, it can only send signals to processes under the same user.
