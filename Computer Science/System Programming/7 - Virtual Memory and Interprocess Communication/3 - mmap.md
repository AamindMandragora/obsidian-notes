Instead of mapping a virtual page to a physical frame, we can map it to a file on disk using `mmap`, then efficiently read from that file, sync changes, and lazy allocate a file to memory. By saving the output of `mmap` to a `char*`, we can tell the kernel to reserve some space in the virtual memory for that file, then directly dereference the pointer and write to the file. The kernel doesn't have to load the entire file, and may only read a couple pages. Page faults let the operating system take control of when a file is used.
# `mmap` Definitions

`mmap` doesn't just map a file to memory, but is the general interface for creating shared memory. Its `flags` argument can take many options: `PROT_READ`, `PROT_WRITE`, `PROT_EXEC`, `PROT_NONE`, `MAP_SHARED` (synced to file), and `MAP_PRIVATE` (only visible to process). Once the program is done with the mapping, it must call `munmap`. We can also call `msync` to sync the changes back from the memory to the file.
# `mmap` Walkthrough

Assume we have some `char* f`, `off_t offset`, and `size_t length`. Then, we must first open the file in `int fd` and get the size through `fstat`. We must create a `size_t page_offset` which equals the offset bitwise-AND the bitwise-NOT of the OS's page size. Finally, we can call `mmap` as follows: `char *addr = mmap(NULL, length + offset - page_offset, PROT_READ, MAP_PRIVATE, fd, page_offset)`. The `NULL` tells `mmap` we don't need any particular starting address, argument two tells it to read starting from `offset`, the next two denote read permissions on the file and a private mapping. Finally, we pass in the file descriptor and the page offset. We can then interact with the address like a normal buffer, then call `munmap` on it and close the file descriptor when we're done.
# `mmap` Communication

To communicate across processes, we'd allocate some space using `mmap`, making sure to share the mapping, then fork the process. We'd then use synchronization primitives to ensure communication happens, and write/read to the `mmap`ed buffer. Each process must call `munmap` once it's finished with the memory. This is efficient IPC as there's no copying, syscall, or disk-access overhead. On the other hand, data races can happen.
