There are four system calls required to create a minimal TCP server. Each serves a specific purpose and should be called in roughly the below order:

`int socket(int domain, int socket_type, int protocol)` creates an endpoint for networking communication and returns a network descriptor. These sockets must be declared passive so they wait for another host to connect and remain open when it disconnects. Clients communicate with a separate active socket on the server specific to that connection. This means there can be one passive server socket but multiple active sockets.

`int bind(int sockfd, constr struct sockaddr *addr, socklen_t addrlen)` associates an abstract socket with an actual network interface and port. The information can be set manually or be generated by `getaddrinfo`. The port isn't immediately released after the server socket is closed unless we specify `SO_REUSEPORT` by calling `setsockopt`.

`int listen(int sockfd, int backlog)` specifies the queue size for the number of incoming connections that haven't been assigned a file descriptor by accept.

`int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen)` waits for new connections and blocks unless told otherwise, only returning when a new client connects. The returned TCP socket is associated with a particular `(client IP, client port, server IP, server port)` tuple that will be used for all future matching packets.

`accept` returns a new file descriptor specific to a particular client, and can optionally provide information about the remote client by passing in a `struct sockaddr`.

Finally, we can call `int shutdown(int fd, int how)` to close the read or write end of a socket, and `close` when the process no longer needs the socket file descriptor. If we forked after creating a socket file descriptor, all processes need to close it before the resources can be reused. However, we can call `shutdown` to affect all processes because it changes the socket directly.

We must make sure to not use the socket descriptor of the passive server socket, specify `SOCK_STREAM` in `getaddrinfo`, not try and reuse an existing port, and initialize unused struct entries.
# Example Server

We first get the address info for our machine, then set up, bind, and listen on the socket. Once we've done that, we can start accepting clients and treat their file descriptors as a stream of bytes like a pipe: 

```c
struct addrinfo hints, *result;
memset(&hints, 0, sizeof(struct addrinfo));
hints.ai_family = AF_INET; // IPv4
hints.ai_socktype = SOCK_STREAM; // TCP
hints.ai_flags = AI_PASSIVE; // server

int s = getaddrinfo(NULL, "1234", &hints, &result); // any machine, port 1234
if (s != 0) {
	fprintf(stderr, "getaddrinfo: %s\n", gai_strerror(s));
	exit(1);
}

// creates an TCP/IPv4 socket
int sock_fd = socket(AF_INET, SOCK_STREAM, 0);
if (sock_fd == -1) {
	perror("socket()");
	exit(1);
}

// binds socket to the first address returned by getaddrinfo
if (bind(sock_fd, result->ai_addr, result->ai_addrlen) != 0) {
	perror("bind()");
	exit(1);
}

// allows up to ten clients in the queue
if (listen(sock_fd, 10) != 0) {
	perror("listen()");
	exit(1);
}

int client_fd = accept(sock_fd, NULL, NULL);

// can read from/write to client
```
# Sorry to Interrupt

Since we're usually waiting for the network, which is ten times slower than processes, we should always expect to get interrupted somewhere, which means we need to handle it everywhere. For example, instead of a single `read` or `write`, we typically put them in a loop that only exits once we see an error or we've read/written all the bytes we expected to.
