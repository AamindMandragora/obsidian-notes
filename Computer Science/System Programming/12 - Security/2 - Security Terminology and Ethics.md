An **attacker** is the user trying to break into the system, which means performing any action that the developer didn't intend. A **defender** is the user attempting to prevent the attacker from breaking in, and can be the developer of the system. Within attackers, there are **white hat** hackers that attempt to hack a defender with their consent as a form of testing. **Black hat** hackers are those who hack without permission and with intent to use the information obtained. **Grey hat** hackers are similar, but don't use the data and only intend to inform the defender of the vulnerability.

The Computer Fraud and Security Act considers all unauthorized use of a protected computer (which is any computer involved in interstate or international commerce, including the Internet) as a felony. We must always find some way to defend ourselves from legal consequences before performing any hack, as our careers can be terminated. If possible, getting written permission from a supervisor can help in the case where an organization tries to pin the blame on an individual. Otherwise, we should first figure out what we're trying to solve and if a hack is even necessary. Then, find a reasonable estimate for the cost of the hack and get it reviewed. At this point, try and get permission. Finally, execute with caution and be ready to terminate.

If there isn't an ethical guideline for what you're attempting, then create one. This is called a **policy vacuum**. In court, you must be able to justify your reaction as one made by a "reasonable" engineer.
# CIA Triad

A system is usually considered secure if its information has confidentiality (only shown to authorized parties), integrity (only modified by authorized parties, not necessarily the same parties as before), and availability (when needed). We can often add authenticity as well. If any of these are broken, the security of a system has been compromised.
